# Pain map — known production failure modes and the Ignis answer

Not a task list. See BRIEF.md "Pain map" rules. Status per item: ADDRESSED / DESIGNED / NOT STARTED, with a link to the hypothesis or ADR.

Re-statused 2026-09-20 against VALIDATION.md through V-105. What moved since the last pass: FrankenPHP 1 and Swoole 1, where per-request service state stopped being a hand-written façade (ADR-0042). Everything else is as it was, including the two rows that still wait on M4-3.

The MVP cut of 2026-09-22 (DECISIONS.md) then deleted the offload pool and the Doctrine package. The rows that cited either are rewritten below to what is true without them — nothing was re-measured for this pass, and where a row's only answer was the deleted mechanism it now says so.

### PHP-FPM
1. Pool exhaustion at low CPU: workers block on I/O, listen queue grows, 502/504 → concurrency decoupled from process count; an I/O wait costs a Fiber, not a worker. — **ADDRESSED** for `Ignis\sleep` (V-2/V-5), for **unmodified tcp stream I/O** (V-12) and for `ssl`/`tls`/`https` (V-25); in-process C I/O that never touches php_stream (libpq, curl) is answered by universal syscall interposition, which parks it with **no PHP hook at all** (the native pgsql pool that used to answer this row was deleted on 2026-09-18, V-87, after V-86 measured it slower than parked `pdo_pgsql`; `SQLite3` is always file-backed, cannot park, and now blocks its PHP thread — ADR-0024) — `curl_exec`/`pdo_pgsql` 100 × 200 ms complete in 279–337 ms on one thread against a 20,337–20,558 ms unhooked control (V-45), and this build is now the default (V-46).
2. Slow-dependency cascade drains the whole pool → per-endpoint fiber budget and circuit breaker on the connection pool. — **BUILT AND GONE AGAIN**: the per-dependency bulkhead and breaker were built on 2026-09-18 (BACKLOG S1-BULKHEAD/M4-2) for the runtime-owned PostgreSQL pool and removed the same day with that pool (ADR-0015 closed, V-87). Nothing in the runtime answers it today: pooling, its bounded wait and any breaker are the application's own, and the userland pool that stood here was deleted with its package on 2026-09-22 (DECISIONS.md). Partially mitigated and measured: a slow dependency that parks costs fibers rather than processes, and every wait can be capped by a wall-clock deadline (V-14: 504 at 102 ms). What is missing is the admission control that stops one endpoint from taking every fiber.
3. Phantom workers: nginx times out, PHP keeps building a response nobody reads → client disconnect cancels the Fiber and its pending futures. — **ADDRESSED** (ADR-0009, V-14: 0.78 ms cancel latency, children included, `finally` runs).
4. Three unaligned timeouts; max_execution_time counts CPU time, not wall-clock → one wall-clock deadline per request, inherited by child fibers and futures. — **ADDRESSED** (ADR-0009, V-14: `Ignis\deadline()` → 504 at 102 ms, inherited by children).
5. Reactive fork-based scaling lag → fibers spawn in microseconds; threads start once. — **ADDRESSED** (V-4: 4.5 µs per job on a warm pool).
6. 30–80 MB per worker; pool sized by RAM → per-request memory is a fiber stack. — **ADDRESSED** with a caveat (V-5: ~34 KB RSS per parked fiber, 16 KiB of it Zend's fixed VM stack; V-10: 26.9 MB RSS serving 64 concurrent requests, 47.0 MB at 500). The fiber budget (pool cap + request queueing) is now **ADDRESSED for admission** (ADR-0019, V-37: 10 concurrent capped at budget 2 serialise to 1028 ms, 10/10 answered; past the queue depth it sheds 503). **The RSS bound is NOT met by it**: a held connection costs ~33 kB regardless of the budget (V-37), so RSS falls ~30% rather than being bounded — capping concurrent connections at the listener is BACKLOG M4-3.
7. Framework bootstrap per request → worker mode, kernel boots once. — **ADDRESSED** for the Ignis API (V-5) and for Symfony (ADR-0011, V-16 + addendum: kernel booted once, 7.2k req/s on 1 thread / 25.2k on 4 with sessions on).
8. No connection pool; pconnect leaks transactions → a pool with a lease per fiber and a session reset on return. — **ADDRESSED IN USERLAND, NOT BY THE RUNTIME** (V-85): the runtime-owned tokio-postgres pool that answered this row (ADR-0015, V-21) was deleted on 2026-09-18 (V-87) — V-86 measured it against parked `pdo_pgsql` and the speed case did not survive. The userland pool that answered it after that was deleted with its package on 2026-09-22 (DECISIONS.md), so **no pool exists in the tree today**. What the docs recommend instead is a connection per fiber — the service holding it marked `scoped` (ADR-0042) — which avoids the sharing defect V-85 measured but is not a pool, has no bounded wait and no session reset on return. The lease-age visibility M4-1 built for the runtime pool is gone with it and is open again as `S-POOL-LEASE-AGE`.

### RoadRunner
1. State discipline pushed to the developer: close descriptors, avoid state pollution, close connections after every iteration → connections belong to the runtime; nothing to close. — **PARTLY ADDRESSED, AND LESS THAN IT WAS**: the runtime-owned PostgreSQL connections this row cited (V-21) were deleted on 2026-09-18 (V-87), and the userland pool that replaced them was deleted with its package on 2026-09-22 (DECISIONS.md), so a connection is the application's to open, own per fiber and close. Nothing is runtime-owned now: a `SQLite3` or file-backed `PDO` handle is the application's too, and its calls block the PHP thread (ADR-0024). MySQL/Redis not started.
2. Leaks handled by memory-limit restarts and gc_collect_cycles per request → allocator-level leak detector in dev, per-thread supervisor in prod, GC scheduled by the runtime off the hot path. — **ADDRESSED** for the runtime itself (V-10: 4.6M requests, PHP heap flat to the byte, no `gc_collect_cycles` per request) and for the per-thread supervisor (V-17: a worker that dies is respawned inside the 50 ms tick, no memory-limit restarts). GC scheduled off the hot path (`IGNIS_LOOP_GC`) is implemented but **not measured** (no V-n; V-11 addendum is the measurement that motivated it). An allocator-level leak detector is NOT STARTED; the fiber-scoped `Ignis\Scope` check (V-11) is the only dev-mode detector today.
3. One request per worker; I/O-bound apps sized by memory → fibers. — **ADDRESSED** (V-5). gRPC evidence in V-20: 100 concurrent 200 ms calls take 5.03 s on RoadRunner with 4 workers and 215 ms on one Ignis thread.
4. Shared state via RPC to Go (KV = network hop) → Table in process memory. — NOT STARTED.
5. Per-request serialization over pipes plus PSR-7 bridges → embedded PHP, request objects built on the Rust side without copies. — **ADDRESSED for the hop, DESIGNED for the copies** (ADR-0002: no pipe and no PSR-7 bridge — one array build per request, strings copied once; "without copies" is not yet true). Measured: V-6 (128k req/s on one thread vs php-fpm's 9.9k over FastCGI). `$_SERVER`/`$_GET`/`$_POST`/`$_COOKIE` now exist per request (V-11), so `Request::createFromGlobals()` works unchanged. V-20 (gRPC): RoadRunner's pipe hop + protobuf-in-PHP gives 5.1k req/s per worker; Ignis serves 16.7k req/s on one PHP thread with the same PHP-side codec work, 79% of a Rust-only tonic server.
6. Bridge reset bugs (leaks on 404, reset broken on exception) → runtime performs reset at fiber end, including abnormal end. — **ADDRESSED** (ADR-0002 + ADR-0006: handler exceptions become 500 and the pooled fiber survives; per-fiber superglobals and scope are discarded when the fiber ends — V-11: 0 mismatches, `{main}` never sees request state). Abnormal ends unwind rather than leak: V-14 (20/20 `finally` blocks ran on cancellation) and V-22 (a rejected future nobody awaits is rethrown instead of being swallowed).
7. musl/Alpine instability → single official artifact: static glibc build. — NOT STARTED.

### FrankenPHP
1. Worker mode requires app adaptation and a leak-free app → same requirement, with tooling: leak detector, fiber-scoped services. — **ADDRESSED** for fiber-scoped services and request state, and since 2026-09-20 with **no app adaptation at all** for the services themselves: ADR-0042 makes an object's declared properties live per fiber, bound at creation, so Symfony's own `RequestStack` and `TokenStorage` classes serve the request and the façades that used to stand in for them are deleted (V-97, V-99–V-101; unmarked control leaks 3/3, marked 0/3, at 1.0–1.1× a plain property's read cost). What the application still does is *name* the services whose state is per-request — `ignis.scoped_ids` or `#[FiberScoped]` — because no container tag expresses it: of Symfony's fifteen `kernel.reset` services, nine are caches shared between requests on purpose (research 36, V-104). Earlier evidence for the row stands: V-11 (0 mismatches at +100 ns/switch), V-16 (0/100), and classic non-worker scripts (V-23: FrankenPHP's testdata through the classic-mode adapter, 29/33 applicable). The leak detector itself is NOT STARTED.
2. Aborted connections stall the server without ignore_user_abort → disconnect is a cancellation event, not a Zend signal. — **ADDRESSED** (V-14).
3. Sizing formula num_threads × memory_limit + GOMEMLIMIT; workers vs threads confusion → one axis: threads = cores, fibers = concurrency, memory = fiber budget; no GC heap. — **ADDRESSED** for threads/fibers (ADR-0004, V-9: `--threads N`, 3.7–3.98× scaling; V-15: least-inflight dispatch); no Go heap, no GOMEMLIMIT. The second axis this row used to name — an explicitly sized pool of offload workers — is gone with that pool (deleted 2026-09-22, DECISIONS.md), so threads and fibers are the only two. The fiber budget (pool cap + queueing) is now **ADDRESSED for admission** (ADR-0019, V-37); **the RSS bound is NOT met by it** — a held connection costs ~33 kB regardless of the budget (V-37) — capping concurrent connections at the listener is BACKLOG M4-3.
4. Thread contention on small CPU: PHP thread yields to hand output to Caddy → buffered response channel, no thread switch per write. — **ADDRESSED** (ADR-0002: one `ignis_respond` per request, oneshot to hyper; V-6: p99 1.11 ms vs FrankenPHP's 6.42 ms on the same box and the same libphp).
5. Hot reload drops custom extensions → modules registered once per process; thread restart never re-registers. — **ADDRESSED** (ADR-0001: module registered in MINIT once; V-17: a worker thread was killed by a fatal and respawned — `restarts=1` — while the process kept serving 134k req/s, with no MINIT and no opcache reset).
6. RestartWorkers must restart all threads because of opcache → single-thread restart without opcache reset; SHM is process-level, thread only recreates its TSRM context. — **ADDRESSED** (ADR-0012, V-17: respawned thread recreates only its TSRM context).
7. cgo boundary cost and thread pinning → native FFI, no stack switch. — **ADDRESSED** (ADR-0001: bindgen; V-2 profile shows Rust at 0.3% of PHP-thread samples).

### Swoole
1. Own coroutines: statics, class state and superglobals change on switch → native Fibers plus superglobal swap on the fiber-switch observer and a fiber-scoped container. — **ADDRESSED** (ADR-0006, V-11: superglobals swapped per fiber at +100 ns/switch, `Ignis\Scope` WeakMap container). **Class state is now covered too** and was not when this row was written: ADR-0042 gives a marked object's declared properties a row per fiber (V-97, V-99–V-101), which is the half of "class state changes on switch" that a key-value bag never reached. Two limits, both named: a value *taken out of* a scoped service and stored in a plain one is still pinned to the request that took it (`S-SINGLETON-CAPTURE`, V-103), and **plain statics remain the app's** (leak detector NOT STARTED).
2. Xdebug/Xhprof incompatibility → Fibers are supported by Xdebug natively. — **DESIGNED** by construction (native `Fiber`, no custom context switching, so no parallel stack for a profiler to miss). **Not validated**: Xdebug is not built against this libphp, so there is no V-n.
3. Forgotten $response->end() holds the connection → response is the Fiber's return value; return or exception closes the connection. — **ADDRESSED** (ADR-0002, `Ignis\serve` handler returns `Response`; exception → 500; cancellation → unwinds, V-14).
4. Deadlock when the only coroutine yields; CPU-heavy work starves others → per-thread watchdog logs long fibers with trace; work-stealing routes new requests to other threads. — **ADDRESSED** (least-inflight dispatch V-15 + watchdog V-17; the watchdog reports the thread, not yet the fiber's trace).
5. Incomplete hooks (curl_multi etc.) → native Rust drivers for HTTP, Postgres, MySQL, Redis; stream-layer hooks for the rest, now superseded by universal syscall-level parking. — **ADDRESSED** for `tcp://` (ADR-0007, V-12), for `ssl://`/`tls://`/`https://` and STARTTLS (ADR-0017, V-25), and — until 2026-09-18 — for PostgreSQL as a native driver (ADR-0015, V-21), now deleted because `pdo_pgsql` parks as well and faster (V-86, V-87). MySQL, Redis and `curl_multi` NOT STARTED; V-7 shows the engine ABI does not cover I/O either. gRPC client added as a native driver (ADR-0014, V-20: `Ignis\Grpc\Client` parks the fiber, 100 × 200 ms in 217 ms). **Since ADR-0037** (the mechanism-budget consolidation), the per-function hook approach for this item is retired: `curl_exec` and `pdo_pgsql` park through universal syscall interposition with **no PHP-level hook at all** — 100 concurrent 200 ms calls in 279–337 ms against a 20,337–20,558 ms unhooked control, `CURLOPT_WRITEFUNCTION` running in the same fiber (V-45, H32/H33); this build is now the **default** (V-46). The per-function `sleep()`/`usleep()` hook, the nine `ext/sockets` hooks, and the `stream_socket_accept()`/`stream_select()` hook (previously E6'', V-26) are **deleted** — their coverage now comes from the same interposer: `sleep`/`usleep` (V-46), `select` (V-47: 201 ms parked vs 601 ms blocked), and the `accept`/`ext/sockets` family including `SO_RCVTIMEO`/`SO_SNDTIMEO` honoured through `park_io` (V-48). The stream transport factory (row 1, `tcp://`/`ssl://`/`tls://`) and the rustls path behind it are **deleted** (V-49, ADR-0037 §6 step 4): a stream op inside a fiber now blocks in libc, the interposed call parks the fiber, and TLS is PHP's own `ext/openssl` on top of that. Two mechanisms are left — park and context — after the MVP cut deleted offload on 2026-09-22 (DECISIONS.md), down from the seven research 29 inventoried.
6. One blocking call stalls the whole process → stalls one thread of N; supervisor sees it via watchdog. — **ADDRESSED** (ADR-0012, V-17: one stalled thread, others at 90k req/s, watchdog reports it). Universal park gives the non-blocking guarantee **without a second thread pool at all**: a parked syscall frees the PHP thread to run other fibers while tokio owns the wait — 100 concurrent `curl_exec`/`pdo_pgsql` calls finish in ~300 ms total on one thread, not serialized (V-45). A call that cannot park — a regular file, `SQLite3`, CPU-bound work — still stalls the one thread that makes it (ADR-0024), and since the offload pool was deleted on 2026-09-22 (DECISIONS.md) there is nowhere to move it to.
7. Fatal kills the worker with every coroutine in it → fatal kills one thread; pools and Table survive. — **ADDRESSED** for the thread part (V-17: one thread dies and is respawned, service uninterrupted). The pool part is **no longer answered by the runtime**: the runtime-owned pool this row cited was measured across a respawn (V-42/V-43 found two defects, both fixed) and then deleted with ADR-0015 on 2026-09-18 (V-87). Any pool today is the application's own, in userland, in the dying thread's own context — so "pools survive a fatal" is **NOT ADDRESSED** again and has no measurement. An in-process Table does not exist (RoadRunner 4).
8. Ecosystem fork (Hyperf, own clients, single listeners) → plain Symfony/Laravel via symfony/runtime, AMPHP via a Revolt driver. — **ADDRESSED for AMPHP** (ADR-0008, V-13: Revolt + amphp examples unchanged on `Ignis\Revolt\IgnisDriver`); Symfony ADDRESSED via symfony/runtime (V-16).

### Engine-level (added by the owner, 2026-09-15)
1. GC-triggered destructors may switch context: a `__destruct` running inside `gc_collect_cycles()` could call `Fiber::suspend()` → the scheduler must forbid or safely handle suspension during GC (Zend already calls `zend_fiber_switch_block()` around GC and destructors of dead fibers, zend_fibers.c/zend_gc.c; Ignis must never resume a fiber from inside a destructor and must treat `FiberError` from a blocked switch as a scheduler bug, not a user error). — DESIGNED (ADR-0003, V-7): `Ignis\Loop` never resumes a fiber from inside a destructor. The second engine backend that had an answer of its own here was deleted on 2026-09-22 (DECISIONS.md), so this one is the only one. Cycle 19 added loop-scheduled GC (`IGNIS_LOOP_GC`: `gc_collect_cycles()` runs at the loop's idle point, off the request path) after V-11's addendum showed the collector walking every pooled fiber inside the timed window. Still **NOT VALIDATED** — no V-n for either the ordering guarantee or the GC scheduling.

### Remains true for Ignis too
Leaks inside C extensions, global statics in third-party libraries (namespace-level constants leak in every worker runtime), thread-unsafe extensions under ZTS. Architecture gives detection, not immunity.
